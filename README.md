# tistory-blog-ops

> **저장소:** https://github.com/EricSeokgon/tistory-blog-ops

티스토리 블로그 2개(`ericreview` · `hadesyi`)의 **기획 → 원고 → 사실검증 → 자동 발행 → 색인 요청 → 효과 측정** 전 과정을 기록하는 운영 저장소입니다. 원고의 정본은 `posts/`이고, 새 세션은 이 README와 `STATE.md`만 읽으면 이어서 일할 수 있게 구성했습니다.

## 새 세션 시작

```
이 저장소(tistory-blog-ops)를 git pull 한 뒤 README.md, STATE.md, PLAYBOOK.md를 먼저 읽어줘.
docs/ 아래 문서로 문체 규격과 티스토리 발행 방법을 파악하고,
docs/plan-2026-Q4.md의 이번 주 표와 STATE.md의 "다음 할 일"부터 이어서 진행해줘.
```

착수 전 확인 세 가지: ① `git pull`(다른 세션이 STATE를 바꿨을 수 있음) ② `TZ=Asia/Seoul date`(세션이 길어지면 `<env>` 날짜가 틀어짐) ③ `www.tistory.com`을 열어 로그인 상태(로그인은 사람만 가능).

## 원칙

1. **발행은 비공개(또는 발행일 유지 교체)부터.** 렌더를 실제 URL에서 확인한 뒤 공개합니다.
2. **사실 검증 없이 발행하지 않습니다.** 세법·규정·수치·버전은 1차 출처, **예시 숫자는 코드로 재계산**(XIRR 9.5%→8.4% 오류를 발행 전 잡은 전례).
3. **하루에 여러 편을 몰아 공개하지 않습니다.** 블로그 단위로 하루 1편 이하.
4. **원고의 정본은 이 저장소입니다.** 티스토리에서 고쳤으면 여기도 반영합니다.
5. **작업한 날은 로그를 남깁니다.** `docs/work-log-YYYY-MM-DD.md` + STATE.md + 이 README의 작업 이력.
6. **비공개→공개 전환은 발행일 갱신까지 한 세트.** 안 하면 RSS·홈에 새 글로 안 뜹니다. 기존 글 **교체는 반대로 발행일 유지**(제목만 수정할 때도 유지).
7. **본문 주입 검증은 1,000자 블록 SHA-256.** 길이만 맞추면 같은 길이의 문자 치환을 못 잡습니다. 10/17부터는 **원고를 먼저 커밋하고 커밋 SHA 고정 raw URL을 fetch해 주입**하므로 base64 전사가 필요 없습니다.
8. **저장소 파일은 git 또는 Upload files로.** GitHub 웹 에디터 타이핑은 줄바꿈이 유실됩니다.
9. **브라우저 자동화에 좌표를 쓰지 않습니다.** 스크린샷 배율이 호출마다 바뀝니다. 요소는 JS로 찾아 `.click()`, 입력은 `focus()` 후 실제 타이핑.
10. **작업 탭은 포그라운드에.** 백그라운드 탭은 타이핑을 삼키거나 일부만 받고 도구는 성공을 보고합니다. 타이핑 직후 값을 문자열로 검증합니다.
11. **새 원고 전에 블로그 자체 검색(`/search/키워드`)과 사이트맵 `og:title` 대조.** GSC 검색어만 보고 "전용 글이 없다"고 판단해 두 번 틀렸습니다. 순위 5~10위에 클릭 0이면 새 글이 아니라 그 글의 본문을 채웁니다.
12. **GSC 실적은 URL 파라미터로 필터.** `&query=*키워드`·`&page=*번호`·`&breakdown=page|query`.
13. **제목 수정은 이미 1페이지에 있는 글의 도구.** 20위 밖이면 제목을 고쳐도 노출이 안 생깁니다.
14. **노출은 큰데 검색어가 하나도 안 잡히는 글은 손대지 않습니다.** 롱테일로 분산된 상태라 타깃을 알 수 없습니다.
15. **세션 착수 전 `git pull`.** 다른 세션의 STATE를 못 보고 색인 큐를 중복 요청해 할당량을 날린 전례(10/15).
16. **마크다운 렌더 함정 사전 치환.** 문장부호 뒤 닫는 `**`+한글은 `<strong>`으로, 홑물결표 `30~50`은 `\~`로 — [`docs/tistory-publishing.md`](docs/tistory-publishing.md) 함정 2.

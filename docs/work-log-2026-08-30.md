## 4. GSC 조작 — 좌표를 완전히 버렸습니다

지난 세션들에서 GSC 자동화의 실패 원인은 거의 전부 **좌표**였습니다. 오늘 좌표 의존을 완전히 제거했습니다.

### 4-1. 스크린샷 배율이 호출마다 달라집니다

같은 세션·같은 창인데 스크린샷 크기가 **1372×887 → 1400×865 → 1315×924** 로 바뀌었습니다. `innerWidth`는 1965로 고정이었습니다. 즉 **배율은 페이지가 아니라 확장 프로그램이 정합니다.**

> ⚠️ **한 배치에서 계산한 좌표를 다음 배치에서 쓰면 빗나갑니다.** 실제로 `/62`에서 이 이유로 클릭이 허공에 떨어졌습니다.

### 4-2. 해결 — 「색인 생성 요청」은 JS 클릭이 먹습니다

```javascript
const t=[...document.querySelectorAll('span,div,button,a')]
  .filter(e=>e.offsetParent&&e.textContent.trim()==='색인 생성 요청');
t[t.length-1].click();
```

Angular 링크라 `el.click()` 한 번으로 정상 동작합니다. **좌표 계산이 통째로 필요 없어졌습니다.**

### 4-3. 해결 — 검색창도 `focus()` + 실제 타이핑

값을 JS로 넣으면 저장되지 않는다는 함정 때문에 그동안 검색창을 **실제 마우스로 클릭**해 왔습니다. 그런데 **포커스만 JS로 주고 타이핑은 실제 키보드로 하면** 문제없이 들어갑니다.

```javascript
document.querySelector('input[type="text"]').focus();
// → 이어서 실제 키보드로 타이핑
```

### 4-4. 성공 모달은 Escape로 닫힙니다

「색인 생성 요청됨」 모달의 「닫기」를 좌표로 클릭하던 것을 **Escape 키**로 대체했습니다. 애니메이션 중이라 `[role=dialog]`가 잠시 남아 있어도 다음 조작에는 지장이 없습니다.

### 4-5. 새 함정 — 타이핑 후 Enter는 히스토리를 고릅니다

`hadesyi/414`를 입력하고 Enter를 눌렀는데 **드롭다운 첫 항목인 `/413`이 검사**됐습니다.

- **해결: 타이핑 → Escape(드롭다운 닫기) → Enter**
- Escape는 입력값을 지우지 않습니다. 값이 남아 있는지 확인한 뒤 Enter를 누르십시오

### 4-6. 새 함정 — 백그라운드 탭은 실제 타이핑을 삼킵니다

탭이 두 개일 때 `document.visibilityState === 'hidden'` 인 탭에 타이핑하면 **`activeElement`는 INPUT인데 값이 들어가지 않습니다.** 도구는 성공을 보고합니다.

> **작업 중인 탭을 포그라운드로 두십시오.** 다 쓴 탭은 `tabs_close_mcp`로 닫는 것이 가장 확실합니다.

### 4-7. 새 함정 — 검사 결과 URL을 `body.innerText`로 읽지 마십시오

`inspect?id=` 뒤의 값은 **URL이 아니라 불투명 해시**입니다(`SST6xPRcc1xLvcd8JhoLYA`). 그래서 딥링크로 특정 URL을 바로 검사할 수 없습니다 — 시도하면 404입니다.

그리고 검사 대상 URL을 `body.innerText`에서 정규식으로 뽑으면 **드롭다운 히스토리나 참조 페이지의 URL이 먼저 잡힙니다.** 실제로 `/414`를 검사 중인데 `/413`으로 오판했습니다. **헤더 요소를 직접 지정해 읽으십시오.**

### 4-8. 카드가 다 그려지기 전에 클릭하지 마십시오

`/10`에서 「색인 생성 요청」을 눌렀는데 90초 넘게 「테스트 중」에 머물다 아무 일도 없이 끝났습니다. 카드가 아직 로딩 중일 때 눌렀기 때문입니다.

> **JS로 「색인 생성 요청」 요소가 존재하는지 확인한 뒤에 클릭하십시오.** 없으면 아직 로딩 중입니다.

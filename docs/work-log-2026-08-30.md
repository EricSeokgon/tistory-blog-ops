## 4. GSC 조작 — 좌표를 완전히 버렸습니다

지난 세션들에서 GSC 자동화의 실패 원인은 거의 전부 **좌표**였습니다. 오늘 좌표 의존을 완전히 제거했습니다.

### 4-1. 스크린샷 배율이 호출마다 달라집니다

같은 세션·같은 창인데 스크린샷 크기가 **1372×887 → 1400×865 → 1315×924** 로 바뀌었습니다. `innerWidth`는 1965로 고정이었습니다. 즉 **배율은 페이지가 아니라 확장 프로그램이 정합니다.**

> ⚠️ **한 배치에서 계산한 좌표를 다음 배치에서 쓰면 빗나갑니다.** 실제로 `/62`에서 이 이유로 클릭이 허공에 떨어졌습니다.

### 4-2. 해결 — 「색인 생성 요청」은 JS 클릭이 먹습니다

```javascript
const t=[...document.querySelectorAll('span,div,button,a')]
  .filter(e=>e.offsetParent&&e.textContent.trim()==='색인 생성 요청');
t[t.length-1].click();
```

Angular 링크라 `el.click()` 한 번으로 정상 동작합니다. **좌표 계산이 통째로 필요 없어졌습니다.**

### 4-3. 해결 — 검색창도 `focus()` + 실제 타이핑

값을 JS로 넣으면 저장되지 않는다는 함정 때문에 그동안 검색창을 **실제 마우스로 클릭**해 왔습니다. 그런데 **포커스만 JS로 주고 타이핑은 실제 키보드로 하면** 문제없이 들어갑니다.

```javascript
document.querySelector('input[type="text"]').focus();
// → 이어서 실제 키보드로 타이핑
```

### 4-4. 성공 모달은 Escape로 닫힙니다

「색인 생성 요청됨」 모달의 「닫기」를 좌표로 클릭하던 것을 **Escape 키**로 대체했습니다. 애니메이션 중이라 `[role=dialog]`가 잠시 남아 있어도 다음 조작에는 지장이 없습니다.

### 4-5. 새 함정 — 타이핑 후 Enter는 히스토리를 고릅니다

`hadesyi/414`를 입력하고 Enter를 눌렀는데 **드롭다운 첫 항목인 `/413`이 검사**됐습니다.

- **해결: 타이핑 → Escape(드롭다운 닫기) → Enter**
- Escape는 입력값을 지우지 않습니다. 값이 남아 있는지 확인한 뒤 Enter를 누르십시오

### 4-6. 새 함정 — 백그라운드 탭은 실제 타이핑을 삼킵니다

탭이 두 개일 때 `document.visibilityState === 'hidden'` 인 탭에 타이핑하면 **`activeElement`는 INPUT인데 값이 들어가지 않습니다.** 도구는 성공을 보고합니다.

> **작업 중인 탭을 포그라운드로 두십시오.** 다 쓴 탭은 `tabs_close_mcp`로 닫는 것이 가장 확실합니다.

### 4-7. 새 함정 — 검사 결과 URL을 `body.innerText`로 읽지 마십시오

`inspect?id=` 뒤의 값은 **URL이 아니라 불투명 해시**입니다(`SST6xPRcc1xLvcd8JhoLYA`). 그래서 딥링크로 특정 URL을 바로 검사할 수 없습니다 — 시도하면 404입니다.

그리고 검사 대상 URL을 `body.innerText`에서 정규식으로 뽑으면 **드롭다운 히스토리나 참조 페이지의 URL이 먼저 잡힙니다.** 실제로 `/414`를 검사 중인데 `/413`으로 오판했습니다. **헤더 요소를 직접 지정해 읽으십시오.**

### 4-8. 카드가 다 그려지기 전에 클릭하지 마십시오

`/10`에서 「색인 생성 요청」을 눌렀는데 90초 넘게 「테스트 중」에 머물다 아무 일도 없이 끝났습니다. 카드가 아직 로딩 중일 때 눌렀기 때문입니다.

> **JS로 「색인 생성 요청」 요소가 존재하는지 확인한 뒤에 클릭하십시오.** 없으면 아직 로딩 중입니다.

## 10. (3차) 신규 원고 — Kubernetes Probe 완전정리

로그인 복구를 기다리는 동안 hadesyi backlog **4순위**를 작성했습니다. 이로써 **backlog의 남은 후보가 전부 소진**됐습니다(ericreview 1순위는 세제개편안 확정 전 대기 상태).

- 파일: `posts/hadesyi/09_Kubernetes-Probes.md`
- 제목: **Kubernetes Probe 완전정리 — Liveness·Readiness·Startup 설계와 흔한 오설정**
- 분량 **10,883자** / H2 12 / 코드블록 12 / 표 4 / 💡4·⚠️3·📎1 / 태그 9
- 태그: `devops, k8s, kubernetes, liveness, probe, readiness, sre, startupprobe, 트러블슈팅`
- K8s 트러블슈팅 트랙(393·399·401·406)의 5편. 401(CrashLoopBackOff)이 probe를 언급만 하고 넘어간 자리를 채웁니다

### 버전 민감 항목 검증 4건

probe는 필드가 몇 개 안 되지만 **버전에 따라 있고 없고가 갈리는 기능**이 있어 공식 문서로 확인했습니다.

| # | 항목 | 결과 |
|---|---|---|
| 1 | gRPC probe | **1.27 GA(stable)** |
| 2 | probe-level `terminationGracePeriodSeconds` | **1.28 stable** · **liveness·startup에만 적용**(readiness는 무의미) |
| 3 | 네이티브 사이드카(`restartPolicy: Always` init container) | **1.28 도입 → 1.33 GA** · probe 3종 전부 사용 가능 |
| 4 | 필드 기본값 | `initialDelaySeconds` 0 / `periodSeconds` 10 / **`timeoutSeconds` 1** / `successThreshold` 1 / `failureThreshold` 3 |

`successThreshold`는 **liveness·startup에서 1로 고정**(변경 불가)이고, **startup probe가 도는 동안 liveness·readiness는 실행되지 않는다**는 동작도 확인했습니다.

### 글의 주장

단순 레퍼런스가 되지 않도록 **설계 판단**을 축으로 잡았습니다.

- **Liveness는 기본으로 넣는 것이 아닙니다.** "재시작으로 풀리는가"가 유일한 기준이고, 아니면 빼는 게 낫습니다
- **Liveness에 의존성 확인을 넣으면 장애 증폭 장치**가 됩니다(DB 흔들림 → 전 파드 동시 재시작 → 커넥션 폭주 → 재발)
- **Readiness에 공유 의존성을 넣으면 전 파드가 동시에 엔드포인트에서 빠집니다.** degraded 응답이 나은 경우가 많습니다
- **`timeoutSeconds` 기본 1초**가 오탐의 최대 원인
- 감지 시간은 `periodSeconds × failureThreshold` — 기본값이면 30초
- 느린 시작은 `initialDelaySeconds`가 아니라 **startup probe**로

진단 절차(`kubectl describe pod` 이벤트에서 `statuscode: 401` vs `context deadline exceeded` 구분, `lastState.terminated.reason`으로 OOMKilled 배제, `kubectl get endpoints`로 readiness 단독 실패 판별)도 넣었습니다.

## 14. (4차) GSC 조작 추가 발견

- **백그라운드 탭 복구는 `focus()`가 아니라 실제 마우스 클릭입니다.** `visibilityState`가 `hidden`이어도 **검색창을 실제 마우스로 한 번 클릭하면** 그 뒤로는 JS `focus()` + 실제 타이핑이 정상 동작합니다. 탭 그룹이 새로 만들어질 때마다 이 한 번의 클릭이 필요합니다.
- **헤더 URL 추출은 드롭다운을 제외해야 합니다.** `body.innerText` 정규식이나 단순 요소 매칭은 **최근 검사 기록 드롭다운의 URL을 먼저 잡습니다.** 실제로 `/403`을 검사 중인데 `/404`로 오판했습니다. **`[role=listbox]`·`[role=option]`·`li` 안쪽을 제외하고 `top < 130`인 요소**만 보십시오.

```javascript
window.__hdr = () => {
  const els = [...document.querySelectorAll('span,div')].filter(e =>
    e.offsetParent &&
    /^https:\/\/hadesyi\.tistory\.com\/\d+$/.test(e.textContent.trim()) &&
    !e.closest('[role=listbox]') && !e.closest('[role=option]') && !e.closest('li') &&
    e.getBoundingClientRect().top < 130);
  return els.length ? els[0].textContent.trim() : null;
};
```

- **드릴다운 표는 기본 10행만 보입니다.** 「페이지당 행 수」를 **500**으로 올려야 전체가 로드됩니다. Material 메뉴라 JS 클릭이 안 먹으니 **실제 마우스**로 열고 고르십시오. 바꾼 뒤 `총 N행 중 1~N`으로 전량 로드를 확인하십시오.
- **성공 판정은 「다시 요청」 문자열로 하십시오.** 성공 모달(`색인 생성 요청됨`)은 페이드아웃되므로 타이밍에 따라 놓칩니다. 카드에 남는 **「✓ 색인 생성 요청됨 · 다시 요청」** 이 더 안정적입니다.
- **색인생성 보고서는 8/30 기준으로도 여전히 8/21에 멈춰 있습니다**(9일째).

# 문체 규격 — HadesYI Dev Story (hadesyi.tistory.com)

기술 블로그. 「주식 한 입」과 완전히 다른 규격입니다. **이모지·해요체를 쓰지 않습니다.**

---

## 제목

```
{주제} {해결 가이드|완전정리|실전 가이드} — {키워드1}·{키워드2}·{키워드3} {선택 기준|원인별 점검}
```

- 트러블슈팅 계열: `{에러명} 해결 가이드 — {원인1}·{원인2}·{원인3} 원인별 점검`
- 개념/설계 계열: `{주제} 완전정리 — {옵션1}·{옵션2}·{옵션3} 선택 기준`
- 본제목과 부제는 **em dash `—`**, 키워드는 가운뎃점 `·`

## 구조 (고정)

```
(제목 없는 리드 문단 — 실제 상황 묘사 1~3문장)

## 핵심 요약               ← 볼드 포함 불릿 5개
## 1. {개념} — {부제}
## 2. ...
   ⋮                      ← 번호 섹션 10개
## 10. 흔한 실수
## 실전 체크리스트          ← 모든 항목이 "~했다"로 끝나는 과거형
## 마치며                  ← 2~4문장
## FAQ                     ← Q1~Q4
## 참고 자료 (또는 참고 공식 문서)   ← 3~4개
## 함께 읽으면 좋은 글       ← 3~4개, 내부 글 제목 그대로
```

**H2 총 16개** (핵심 요약 + 번호 10 + 체크리스트 + 마치며 + FAQ + 참고 + 함께읽으면 = 16)

## 리드 문단

제목 없이 바로 시작. **현장에서 실제로 마주치는 장면**을 묘사하고, 마지막에 이 글이 다룰 지점을 지정합니다.

실제 예:

> 애플리케이션 로그에는 아무 에러도 없는데 Pod가 조용히 재시작을 반복하는 상황. `kubectl logs`를 아무리 뒤져도 스택트레이스가 없고, 마지막 줄은 평범한 요청 처리 로그에서 끊겨 있습니다. 이 침묵이 OOMKilled의 특징입니다. 프로세스가 예외를 던지고 죽은 게 아니라, **커널이 예고 없이 SIGKILL을 보냈기 때문**입니다.

시리즈물이면 앞선 글을 명시적으로 참조합니다: "앞선 글에서 문서 구조 분석이 전처리의 시작점이라고 정리했는데, 그 구조를 실제로 청크 경계에 반영하는 단계가 오늘의 주제입니다."

## 문체

- **합니다체 / 하십시오체.** `~합니다`, `~입니다`, `~하십시오`
- **해요체(`~해요`, `~죠`) 금지** ← ericreview와 결정적으로 다른 점
- **이모지 사용 금지**
- 볼드는 문장 중간 핵심구에 사용
- 인라인 코드는 백틱: `kubectl describe pod`, `memory.max`
- 블록쿼트(`>`)는 **주의사항·핵심 정리**에 사용. 이모지 접두어 없음

## 「핵심 요약」

볼드를 포함한 불릿 **5개**. 각 항목이 독립적으로 읽혀야 합니다.

```
- OOMKilled는 애플리케이션 오류가 아니라 **cgroup 메모리 한도를 넘겨 커널이 내린 강제 종료 판정**입니다.
- 첫 명령은 앞선 세 편과 같습니다. `kubectl describe pod`로 **`Last State`의 `Reason`** 을 확인하십시오.
...
```

## 「10. 흔한 실수」

`- **{실수}** — {왜 틀렸는지}` 형태로 7~9개. **실무에서 실제로 자주 보는 것만** 넣습니다.

---

## 「실전 체크리스트」

모든 항목이 **`~했다`** 과거형으로 끝납니다. 작업 후 스스로 점검하는 용도이기 때문입니다.

```
- 임베딩 모델의 최대 입력 토큰 수를 확인하고 청크 크기를 그 아래로 잡았다.
- 표·코드블록을 크기 기준 분할 대상에서 제외했다.
```

10~13개.

---

## 「마치며」

2~4문장. 그 주제를 바라보는 **관점의 재정의** + 실무 조언.

> OOMKilled는 장애라기보다 **커널이 남긴 영수증**입니다. "이 컨테이너가 약속한 한도를 넘겼다"는 사실만 정확히 기록되어 있고, 왜 넘겼는지는 적혀 있지 않습니다.

---

## 「FAQ」

`**Q1. {질문}**` → 다음 줄부터 답변 문단. **Q1~Q4 고정.**

실제로 나올 질문을 쓰고, 답변에서 **구체적인 명령어나 설정값**을 제시합니다.

## 태그

- **정확히 9개**
- 영문 기술 용어 + 한글 개념어 혼용, 띄어쓰기 없음
- 예: `cgroupv2, ExitCode137, JVM튜닝, Kubernetes, OOMKilled, VPA, 메모리누수, 쿠버네티스, 트러블슈팅`

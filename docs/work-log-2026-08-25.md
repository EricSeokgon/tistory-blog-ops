### base64 주입 시 겪은 문제와 해결 (다음 세션 참고)

원고를 base64로 나눠 주입하는 과정에서 **AI 전사 오류로 키릴 동형문자(О·Т·К 등)가 섞여** atob 디코딩이 실패했습니다. 해결 절차:

1. **누적 길이를 조각마다 정확히 확인** — 6KB 조각은 오류가 많으니 **3KB 조각(10개)**으로 나누고, 각 조각 후 `window.__B64.length`가 정확히 배수인지 확인
2. **비ASCII 검출** — `[...s].filter(c=>c.charCodeAt(0)>127)`로 키릴 동형문자를 찾아 ASCII로 정규화(О→O, Т→T, К→K, Р→P, С→C, Е→E, А→A, В→B, М→M, Н→H, Х→X, Б→B, Д→D, У→Y 등)
3. **최종 검증** — 누적 후 `atob`+`TextDecoder`로 복원해 **바이트 수가 원본과 일치**(이번엔 22,498)하고 head/tail이 맞는지 확인한 뒤에만 주입 진행
4. 27000처럼 4의 배수 지점까지는 부분 `atob`로 중간 검증 가능

> 요약: base64 조각은 **3KB 이하로 잘게, 각 조각마다 길이·비ASCII를 확인**하고, 최종 디코드 바이트 수를 원본과 대조하는 것이 안전합니다.

## 7. 공개 상태 재검증 — "주식 한 입에 게시된 게 없다"는 지적에 대한 확인

사용자가 **"주식 한입은 게시된게 없는데"** 라고 지적해, 로그인 상태의 관리 페이지가 아니라 **로그아웃 상태의 실제 공개 URL**로 다시 검증했습니다. 관리 페이지의 `비공개` 표시는 화면 상태일 뿐이므로, 외부 방문자가 실제로 볼 수 있는지가 유일한 증거입니다.

### 검증 방법

티스토리 세션이 만료돼 로그아웃된 브라우저에서 각 글 URL을 직접 열었습니다. 비공개 글이면 본문이 없는 빈 페이지(제목 `TISTORY`)가 뜹니다.

| ID | 제목 | 로그아웃 접근 | 본문 길이 | 판정 |
|---|---|---|---|---|
| 101 | 파킹통장·CMA·MMF 완전정리 | ✅ 정상 렌더 | 4,518자 | **공개 확인** |
| 102 | 국내상장 해외 ETF vs 해외상장 ETF | ✅ 정상 렌더 | 4,383자 | **공개 확인** |
| 103 | TDF 완전정리 | ❌ 빈 페이지(제목 `TISTORY`) | 93자 | 비공개 (예정대로) |

블로그 첫 페이지(`ericreview.tistory.com/`)의 **본문 목록(`.post-item`)** 최상단 3건도 `102 · 101 · 100` 으로 확인했습니다. 사이드바 위젯이 아니라 메인 리스트입니다.

**결론: 101·102는 실제로 공개돼 있습니다.** 8/24·8/25 공개 전환 보고는 정확했습니다.

### 그런데 왜 "게시된 게 없어" 보이나 — 진짜 원인

두 글의 화면 표기 날짜가 **`2026. 8. 17.`** 입니다. 8/17은 이 글들을 **비공개로 저장한 날**이고, 8/24·8/25에 공개로 전환했는데도 날짜가 그대로입니다.

티스토리는 **비공개→공개 전환 시 발행일을 갱신하지 않습니다.** 최초 저장 시각이 그대로 발행일이 됩니다. 그 결과:

- 블로그 자체 목록에서는 상단에 뜨지만 **날짜가 8일 전**이라 새 글로 보이지 않습니다
- **RSS·구독 피드·티스토리 홈**은 발행일 기준으로 정렬·노출하므로, 8/17자 글은 이미 지나간 구간에 꽂혀 **신규 노출이 발생하지 않습니다**
- 다음(Daum) 검색의 신규 수집도 같은 이유로 약해집니다

즉 "공개는 됐지만 **새 글로 알려지지 않은** 상태"입니다. 사용자가 체감한 것은 이 부분으로 보입니다.

## 8. 발행일 갱신 + 103 공개 전환 (3회차 앞당김)

7번에서 확인한 **"공개해도 발행일이 안 바뀌어 새 글로 노출되지 않는다"** 문제를 실제로 처리했습니다. 사용자 요청으로 3회차를 앞당겨 ericreview 3편을 한 번에 정리했습니다.

### 절차 (검증됨)

에디터를 열어야 하므로 글 관리 체크박스 방식은 쓸 수 없습니다.

1. `/manage/newpost/{id}` 진입 — **기존 글 수정은 진입 확인창이 뜨지 않습니다**(신규 글쓰기와 다름). 확인함
2. 우하단 **「완료」** 클릭 → 발행 패널 오픈
3. 비공개 글이면 먼저 **「공개」 라벨 클릭** — 이때 비로소 `현재`·`예약` 버튼과 「공개 발행」 버튼이 나타납니다
4. `button.btn_date` 중 **「현재」** 클릭 → 클래스가 `btn_date on`으로 바뀌는지 확인
5. **「공개 발행」** 클릭 → 10~16초 후 `/manage/posts/`로 리다이렉트

```javascript
// 발행일 갱신 핵심
const b=[...document.querySelectorAll('button.btn_date')].filter(x=>x.offsetParent);
b.find(x=>x.textContent.trim()==='현재').click();
// 검증: 'btn_date on'이 「현재」로 옮겨갔는지
// 비공개→공개는 라벨 클릭이 선행되어야 함
[...document.querySelectorAll('label')].find(l=>l.offsetParent&&l.textContent.trim()==='공개').click();
```

> 발행 패널의 라디오 값: **20 = 공개 / 15 = 공개(보호) / 0 = 비공개**. 비공개 상태에서는 날짜 버튼이 1개(기존 날짜)만 보이고 하단 버튼도 「비공개 저장」으로 표시됩니다.

### 임시저장 버튼 위치

하단 바의 `a.action`(텍스트 `임시저장`)이 **저장 실행**이고, 그 옆의 숫자 배지는 **저장 목록 열기**입니다. 둘은 다른 동작이므로 구분해서 클릭해야 합니다.

### base64 전사 오류 — 해결책 확정

이번에도 전사 중 오차가 났습니다(총 5군데). 기존의 "길이 확인 + 비ASCII 검출"로는 **같은 길이의 문자 치환을 못 잡습니다.** 실제로 길이는 맞는데 내용이 다른 블록이 4개 있었습니다.

**확정 절차 — 1,000자 블록 SHA-256 대조:**

```bash
# 로컬: 블록별 해시 생성
python3 -c "

    print(i, hashlib.sha256(s[i:i+1000].encode()).hexdigest()[:12])

sha256sum /tmp/06.b64   # 전체 해시도 확보
```

**핵심 이점:** 틀린 블록만 다시 보내면 되므로 전체를 다시 전송할 필요가 없습니다. 순서가 뒤바뀐 경우(이번에 조각 02·03 누락)도 뒷부분을 `__TAIL`에 보관했다가 되붙여 복구했습니다.

최종적으로 **전체 SHA-256이 원본과 일치**(`22551d3fbf80…`)했고, 디코드 바이트 수도 23,014로 정확히 맞았습니다.

## 2. 8/26 결론 정정 — 리디렉션 오류는 해소되지 않았습니다

8/26 로그에 **"`/m/` 경로가 200 + canonical 정상이므로 리디렉션 원인은 해소됨"** 이라고 적었습니다. **틀렸습니다.**

`/71`을 URL 검사로 조회한 결과입니다.

```
페이지 색인이 생성되지 않음: 리디렉션 오류
최근 크롤링:   2026. 8. 26. 오후 9:48:44   ← 7/24에서 갱신됨
에이전트:      Googlebot 스마트폰
크롤링 허용:   예

```

좋은 소식과 나쁜 소식이 같이 있습니다.

- ✅ **재크롤링은 실제로 일어났습니다.** 최근 크롤링이 7/24 → **8/26 21:48**로 갱신됐습니다. 색인 요청이 작동했다는 증거입니다
- ❌ **그 크롤링에서도 리디렉션 오류로 실패했습니다.** 문제가 살아 있습니다

### 그런데 실시간 테스트는 통과합니다

같은 URL로 **「실제 URL 테스트」** 를 돌렸습니다.

```
2026. 8. 29. 오전 9:48에 테스트됨
✅ URL을 Google에 등록할 수 있음
✅ 페이지 공개 상태: 페이지 색인을 생성할 수 있음
```

**지금 Googlebot이 가져오면 정상입니다.** 8/26 크롤링만 실패했습니다.

### 해석 — 간헐적 실패

두 결과를 합치면 결론은 하나입니다. **리디렉션 오류는 상시가 아니라 간헐적입니다.**

- 데스크톱 브라우저로 열면 정상 (8/26 확인)
- 실시간 Googlebot 테스트도 정상 (8/29 확인)
- 그런데 실제 크롤링 시점에는 실패 (7/24, 8/26 모두)

티스토리가 특정 조건 — 부하, 캐시 미스, 봇 트래픽 급증 — 에서 리디렉션을 반환하는 것으로 보입니다. **우리가 고칠 수 있는 문제가 아닙니다.**

> 💡 **대응은 반복 요청뿐입니다.** 실시간 테스트가 통과하는 순간에 색인 요청을 넣으면 우선순위 큐에 들어가므로, 성공 확률이 높은 타이밍에 재시도하는 셈이 됩니다. **실시간 테스트 → 통과 확인 → 즉시 색인 요청** 순서를 권장합니다.

### 두 번 막혔던 이유

1. **8/27** — 글쓰기에 사용자의 「좋은 코드 리뷰」 초안이 복원돼 있어 덮어쓰지 않으려고 중단
2. **8/29 1차** — 빈 에디터 확보에는 성공했으나 주입 도중 **탭 그룹이 초기화**되며 `window.__B64`가 소실. 재진입하려니 **티스토리 세션 만료**

> 사용자의 초안(412번 「리뷰는 코드를 보는 일이 아니라, 사람에게 말하는 일이다」)은 **8/29 09:18에 정상 발행**된 것을 확인했습니다. 제 작업으로 인한 손실은 없었습니다.

### 전송 방식 개선 — gzip 압축 (신규 표준)

같은 실패를 반복하지 않으려고 주입 페이로드를 압축했습니다.

```bash
gzip -9 -c posts/hadesyi/07_vLLM-Structured-Outputs.md | base64 -w0 > /tmp/v7.gz.b64
```

| 방식 | 길이 | 블록 수 |
|---|---|---|
| 기존 base64 | 27,456자 | 28 |
| **gzip + base64** | **11,232자** | **12** |

**59% 감소**입니다. 브라우저에서는 `DecompressionStream('gzip')` 으로 복원합니다.

```javascript
const bytes = Uint8Array.from(atob(window.__B64), c=>c.charCodeAt(0));
const stream = new Blob([bytes]).stream().pipeThrough(new DecompressionStream('gzip'));
const buf = await new Response(stream).arrayBuffer();
window.__MD = new TextDecoder('utf-8').decode(buf);
```

> **앞으로 base64 주입은 gzip 압축을 기본으로 하십시오.** 전송량이 절반 이하로 줄어 전사 오류 확률과 중단 위험이 함께 내려갑니다. `DecompressionStream`은 최신 크롬에서 기본 제공됩니다(`typeof DecompressionStream === 'function'` 으로 확인).

### 이번에도 블록 해시가 잡아냈습니다

12블록 중 **0번 블록**이 어긋났습니다. 250자 단위로 좁혀 보니 **맨 앞 250자**만 문제였고, 그 조각만 교체하니 전체 SHA-256이 일치했습니다(`6331bdd70055`). 압축 데이터는 한 글자만 틀려도 `DecompressionStream`이 통째로 실패하므로, **압축 방식에서는 해시 검증이 선택이 아니라 필수**입니다.

디코드 후 바이트 수도 20,591로 원본과 정확히 일치했습니다.

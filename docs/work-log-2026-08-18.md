- 카테고리 `AI·LLM 엔지니어링`, 태그 9개 부착, 공개 범위 **비공개**

### 새 함정 — 글쓰기 페이지 진입 직후 뜨는 네이티브 확인창

`docs/tistory-publishing.md`는 네이티브 확인창을 "에디터 모드 전환 시" 발생하는 것으로만 기록하고 있는데, **페이지 진입 직후에도 발생합니다.**

- 임시저장된 글이 있으면 `/manage/newpost/` 진입 직후 티스토리가 네이티브 `confirm()`을 띄웁니다 (「작성 중인 글이 있습니다. 이어서 작성하시겠습니까?」 계열).
- 이 창은 **페이지 로드 시점에 뜨므로 1단계의 `window.confirm` 무력화 코드보다 먼저 실행됩니다.** 즉 1단계 무력화로는 원천적으로 막을 수 없습니다.
- 창이 떠 있는 동안 렌더러가 통째로 멈춰 **스크립트 실행·스크린샷·DOM 조회가 전부 타임아웃**되고, 사용자가 직접 눌러야만 복구됩니다.
- **증상 식별법:** 탭 제목은 「글쓰기」로 정상인데 모든 브라우저 호출이 타임아웃되면 이 확인창입니다.
- **대처:** 자동화를 시작하기 전에 사람이 한 번 진입해 확인창을 처리하거나, 임시저장 글을 미리 비워 두십시오. 복구된 뒤 1단계 무력화 코드를 즉시 실행하면 이후 모드 전환 확인창은 정상적으로 억제됩니다.

> 같은 원리로 **GitHub 웹 에디터의 "Cancel changes"** 도 `beforeunload` 확인창을 띄워 탭을 멈춥니다. 저장소 파일 수정은 웹 에디터 타이핑 대신 **Upload files 방식**(파일 업로드 → 커밋)을 쓰는 편이 안전합니다. 실제로 이번 세션의 커밋은 전부 업로드 방식으로 처리했습니다.

### 검증된 발행 절차 (이번에 실제로 통과한 순서)

1. 대상 브라우저에서 티스토리 로그인 + 확장프로그램에 `hadesyi.tistory.com` 허용을 먼저 확인
2. `/manage/newpost/` 진입 → **확인창이 뜨면 사람이 「취소」** (새 글로 시작)
3. 즉시 다이얼로그 무력화 코드 실행 (`window.confirm`/`alert`/`prompt`/`onbeforeunload`)
4. **원고 전달** — 마크다운을 base64로 인코딩해 6KB 단위로 나눠 `window.__B64`에 누적한 뒤 `atob`+`TextDecoder`로 복원. 누적 후 `replace(/\s/g,'')`로 공백을 제거하고 **바이트 수를 원본과 대조**하십시오(이번에 공백 1자가 섞여 들어간 것을 이 대조로 잡았습니다).
5. 제목은 네이티브 setter, 본문은 `marked.parse` → `tinymce.setContent` → `triggerSave`. 주입 직후 `data-ke-` 속성이 붙으면 정상입니다.
6. 카테고리는 **마지막 설정을 기억**합니다. `.btn-category` 텍스트로 먼저 확인하고, 이미 맞으면 건드리지 마십시오.
7. 태그는 `#tagText`를 클릭한 뒤 실제 키 입력 + Enter를 태그 수만큼 반복 (JS 값 주입으로는 확정되지 않습니다)

9. 저장 후 `/manage/posts/`에서 글 번호를 찾아 실제 URL로 본문 길이·표·코드블록을 검증
